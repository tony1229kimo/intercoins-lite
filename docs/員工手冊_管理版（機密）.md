## 二、後台操作

### 登入
個人帳號密碼（不是共用密碼）。密碼不存在瀏覽器，關掉分頁就要重新登入。
**每一次調閱名單都會寫入稽核紀錄**（誰、何時、看了哪一份、來源 IP）。

### 上方六個數字
只有兩個會變紅 —— 紅了就是有待辦：

- **待聯繫名單**：中了 `contact` 類獎項但還沒留聯絡資訊的人數
- **推播失敗**：券沒送進客人 LINE 的筆數 → 要補送

### 三個分頁

| 分頁 | 用途 |
|---|---|
| **待聯繫名單** | 依這份主動聯繫（含臺北全部與高雄的兩項住宿大獎）。篩「只看未填」的那些**不用人工催** —— 客人下次開遊戲系統會自動再問，直到填完 |
| **中獎名單** | **兩館共用一份**，可依館別／獎項類型篩選。最實用的篩選是「**實體獎・尚未領取**」＝待辦清單。可下載 CSV |
| **獎項與庫存** | 每個獎的實際機率、名額、已發出、剩餘 |

### 「狀態」欄
| 顯示 | 要做什麼 |
|---|---|
| 券已領取 / 券未領取 / 直接入帳 | 不用處理 |
| **推播失敗** | **要處理** —— 補送 |
| 已留聯絡資訊 | 臺北的人主動聯繫 |
| 待客人填寫 | 不用催，系統會自動再問 |

## 四、🔒 獎池容量 —— 上線前必須決策

**目前的獎池只夠約 31 位玩家玩完，全部獎品就發光了。**

### 為什麼

1. 轉盤是「全獎盤」，**每抽必中**
2. 「洲遊幣 +N」是**全額退幣**（投 1 中 +1、投 3 中 +3、投 5 中 +5）＝ 免費再抽一次
3. ⇒ **客人手上的每一枚洲遊幣，最終都會換成一件實體獎**

| | 數字 |
|---|---:|
| 實體獎總名額 | 132 份 |
| 可吸收的洲遊幣 | 90×1 + 26×3 + 16×5 = **248 枚** |
| 每人可賺（8 個任務各 1 枚） | **8 枚** |
| **可支撐玩家數** | **248 ÷ 8 ≈ 31 人** |

### 反直覺重點：加任務會讓可服務人數變少

| 每人可賺 | 可支撐玩家 | 一等獎（投 5 枚） |
|---:|---:|---|
| 4 枚 | 62 人 | ❌ 抽不到 |
| 6 枚 | 41 人 | ✅ |
| **8 枚（現況）** | **31 人** | ✅ 抽完還剩 3 枚 |

任務數是**社群成長**的槓桿，玩家數是**獎品庫存**的槓桿 —— 兩者互相拉扯。

### 可以怎麼調

| 做法 | 效果 | 代價 |
|---|---|---|
| **A. 增加獎品名額** | 最直接。名額 ×3 → 約 93 人；×10 → 約 310 人 | 要真的有庫存與預算 |
| **B. 加「銘謝惠顧」格並扣幣** | 讓幣可以消失，中獎率由行銷控制 | 不再是全獎盤，體驗要重新說明 |
| **C. 減少任務或降低幣值** | 每人幣數少 → 服務更多人 | 社群曝光變少 |
| **D. 維持現狀，當小規模體驗活動** | 不用改任何東西 | 第 31 人之後客人抽到的都是「銘謝惠顧」（不扣幣） |

> A～C **只要改資料、不用改程式**，也不用重新部署 —— 決定後告知即可調整。

**目前發完後的行為**：轉盤照轉、停在格線之間、跳「銘謝惠顧 / 本等級獎項已全數送出」，
**不扣客人的洲遊幣**，並明白告知可改抽其他等級。

## 五、🔒 個人資料與稽核

| 項目 | 說明 |
|---|---|
| 蒐集了什麼 | 姓名、手機、Email、LINE UserId、LINE 顯示名稱 |
| 存在哪 | Zeabur Postgres（台北機房）。**不在 GitHub、不在任何檔案** |
| 誰看得到 | 只有 `ADMIN_USERS` 名單內的人，且每次調閱都留紀錄（`admin_access_log`） |
| 客人的同意 | 活動頁的「個資告知事項」；兩館**分別**勾選、互不共享未授權資料 |
| 移除某人的存取 | 從 `ADMIN_USERS` 拿掉他那組，重新部署即可，其他人不受影響 |

### 🚨 Omnichat 兌換連結的風險

程式碼庫裡有 **17 條 Omnichat 兌換連結**。這些連結是 **stateless** 的 ——
**任何人拿到就能直接領券**，不需登入也不需中獎。

- ❌ 程式碼庫**必須永遠保持 private**
- ❌ 不可把獎項設定檔貼進任何對外文件、簡報、Slack
- ✅ 若懷疑外流，請行銷到 Omnichat 後台**重新產生連結**，再請 Tony 重跑匯入

> 應用層我們已包一層「單次有效」保護（客人點過一次就失效），
> 但**原始連結本身沒有任何保護**。

## 六、帳號管理

Zeabur → `intercoins-lite` 專案 → `intercoins-lite` 服務 → 環境變數 → `ADMIN_USERS`

```
ADMIN_USERS=tony:密碼A,kh-mktg:密碼B,tpe-mktg:密碼C
```

- 多組用**逗號**分隔，帳號密碼用**冒號**分隔
- ⚠️ **密碼裡不能有逗號或冒號**
- 改完**一定要按「重新部署」** —— 容器只在啟動時讀環境變數
- 驗證：`curl -s https://intercoins.ictaiwan.net/api/health`
  看 `admin_users_configured` 是否等於設定的帳號數

## 七、狀況處理

| 狀況 | 處理 |
|---|---|
| 客人沒收到券 | 中獎名單搜姓名／兌換碼 → 狀態「推播失敗」→ 補送；「券未領取」→ 請他在 LINE 對話往上找 |
| 客人說券「已使用過」但堅稱沒領 | 查 `claim_used_at` 時間。系統為防無限領取，每張券只能領一次 |
| 中獎者遲遲沒填聯絡資訊 | **不用人工催**，系統會在他下次開遊戲時自動再問 |
| 某等級獎品發完 | 客人會抽到「銘謝惠顧」且不扣幣。要繼續發獎需增加名額 |
| 懷疑有人異常大量中獎 | 查中獎名單同一 LINE UserId 的筆數；洲遊幣有上限（每人 8 枚），正常不會異常 |
| 系統整體異常 | `curl -s "https://intercoins.ictaiwan.net/api/health?deep=1"` 看 `db`、LINE token 是否有效 |
